# Предложение: конвенция типизации optional-полей публичного API

## Одной строкой

Публичные типы `.d.ts` местами расходятся с тем, как компонент ведёт себя в
рантайме. Это даёт пользователям (особенно Angular `strictTemplates`) **ложные
ошибки компиляции** на корректном коде. Есть простое механическое правило, которое
это чинит, и **eslint-правило, которое уже его проверяет** — разработчику не надо
помнить конвенцию, редактор подсказывает сам.

---

## Проблема (зачем вообще)

Три слоя живут независимо и расходятся: **тип** в `.d.ts`, JSDoc **`@default`**,
рантайм **`defaultOptions`**. Единого правила нет.

**Прямое следствие для пользователя.** Форма типа в `.d.ts` определяет, можно ли
легально написать `[input]="undefined"`. Если тип уже рантайма — пользователь
получает ошибку компиляции на коде, который работает:

```
[type]="undefined"   →   error TS2322: Type 'undefined' is not assignable to type 'MessageType'.
```

Это не гипотетика — воспроизводится в изолированной песочнице (раздел 2
обоснования) и бьёт по реальным паттернам Angular: `[input]="obs$ | async"`
(async-pipe до первого значения отдаёт `null`/`undefined`), `[input]="signal()"`,
просто `[input]="undefined"`. Подтверждено внутренним баг-репортом
[T1093403](https://isc.devexpress.com/internal/ticket/details/T1093403)
(I. Kharchenko, 2022): обёртка генерит `width(): number | Function | string` без
`| undefined` → `[width]="undefined"` не биндится.

Почему именно `| undefined`: генератор обёрток **теряет `?`**, поэтому единственный
способ выразить «значение не задано» в Angular/React/Vue-обёртке — явный
`| undefined` в исходном `.d.ts`.

---

## Решение — конвенция + инструмент

1. **Конвенция** ([OPTIONAL_FIELDS_CONVENTION.md](OPTIONAL_FIELDS_CONVENTION.md)) —
   механическое правило из двух осей: `| undefined` ставим только опциям со seed
   `undefined`; `@default` пишем только если значение реально хранится. Правило —
   для **нового** кода; существующее приводим **без breaking changes** (расширяем тип
   под рантайм, рантайм не трогаем — детали ниже).

2. **Инструмент — главное.** Конвенцию **не нужно держать в голове**. Это не «ещё одна
   конвенция, которую соблюдают руками», а **тул, снижающий нагрузку**. Энфорсмент
   двухслойный:
   - **линтер** `devextreme-custom` подсвечивает механику (тип ↔ `@default`) прямо в
     редакторе и в `lint-dts`; ратчет в CI не даёт нарушениям расти;
   - **ревью (GitHub Copilot)** через `API_conventions.instructions.md` ловит смысловой
     выбор, который линтер сделать **не может**: `undefined` или `null` в новом поле.

   > Внесение правила в `API_conventions.instructions.md` — следующий шаг (после
   > согласования); он же включает слой Copilot-ревью.

---

## Что это значит для публичного API (для Product Managers)

Менять публичные типы — потенциально **breaking change**, и мы относимся к этому
серьёзно. Поэтому политика — **без breaking changes для существующего кода**: правило
нормативно для нового, существующее приводим только в сторону **расширения**. Eslint
флагает **715** мест (630 hard + 85 review); вот как они чинятся:

| Бакет | Кол-во | Как чиним | breaking? |
|---|---|---|---|
| **doc-only** | **213** | JSDoc `@default` / поведение в описание (R4=128, R5=85) | **нет** — тип не меняется (только генерируемая дока) |
| **widening / fix** | **472** | расширяем тип под рантайм: `+ \| null` (R1=399) / `+ \| undefined` (R6=73) | **нет — это FIX**: старый код компилируется как раньше, ложные ошибки `strictTemplates` уходят |
| **narrowing** | **30** | сузить тип (убрать `\| undefined`, R2) — **НЕ делаем** (это BC) | **0 действий** — оставляем как терпимый легаси-варнинг |

**Почему расширение безопасно:** добавить `| null`/`| undefined` к типу — это widening
(старый код валиден, новый может больше); вдобавок `+ | undefined` **чинит** баг
[T1093403](https://isc.devexpress.com/internal/ticket/details/T1093403). Ломает только
**сужение** — а его по политике no-BC мы **не выполняем**.

**Что с теми 30 «narrowing»?** Это R2 (конкретный `@default` при `| undefined` в типе) —
6 имён полей, почти все в viz:

| Поле | Компоненты |
|---|---|
| `color` | charts, funnel, pie_chart, polar_chart, sankey, tree_map |
| `dashStyle` | charts, chart, pie_chart, polar_chart |
| `width` | funnel, sankey, tree_map |
| `visible` | funnel, sankey |
| `value` | check_box |
| `opacity` | sankey |

Привести их к «идеалу» нового правила (убрать `| undefined`) = сузить тип = BC. Поэтому
**не трогаем**: остаются `| undefined` с конкретным `@default` (линтер варнит, потребитель
не страдает). То же с `dataSource` (`| null` ×42): убрать = BC → оставляем как терпимый
легаси (рантайм lint не видит — тип и `@default` между собой согласованы).

**Итог для PM: предложение не ломает ни одного потребителя. Net breaking changes = 0.**

> **Отдельно и опционально (будущий major).** Если захотим довести API до идеала —
> убрать избыточный `| null` (dataSource и т.п.) и мигрировать рантайм `null → undefined` —
> это уже **breaking** (меняет возврат `option()` и компиляцию `[x]="null"`), поэтому
> только осознанным major с планом совместимости. **Вне этого предложения**, согласование
> не блокирует.

---

## Предложение

**Само предложение — без breaking changes.** Конвенция применяется к новому коду;
существующее приводим только расширением типа (widening) и правкой доков — потребители
не ломаются, наоборот, уходят ложные ошибки `strictTemplates`. PM не выбирает «ломать
или нет» — предложение non-breaking по построению.

Решение сводится к одному: **согласовать конвенцию как общую** (правило + линтер уже
есть) и дать командам гасить легаси-варнинги в своём темпе. Ратчет гарантирует, что хуже
не станет; пилот (`chat.d.ts`) задаёт эталон стиля.

**Опционально и отдельно — чистка `null` (будущий major).** Если решим довести API до
идеала (убрать избыточный `| null`, мигрировать рантайм `null → undefined`) — это уже
breaking, поэтому только осознанным major с планом совместимости. Это **карта на потом**,
не часть текущего согласования.

---

## Что НЕ делаем прямо сейчас

- Не вносим правило в `API_conventions.instructions.md` — это следующий шаг после согласования.
- Не делаем массовую правку — сначала пилот (`chat.d.ts`) как эталон стиля, потом по командам.
- Не сужаем типы существующих полей и не мигрируем рантайм `null → undefined` (это BC) —
  чистка `null` отложена в опциональный будущий major.
- Не выкатываем большой документ-обоснование как «конвенцию» — он остаётся reference.

## Дальнейшие шаги (после согласования)

1. Пилот `chat.d.ts` → смерженный PR-эталон.
2. Внести правило в `API_conventions.instructions.md`.
3. Разбить нарушения на globs по 4 командам; DoD команды = её globs переведены в `error`.
4. Burn-down: число нарушений в baseline 630 → 0; трекаем на роадмапе.
